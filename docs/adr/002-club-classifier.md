# ADR 002 — 드라이버/아이언 자동 판별: 사전학습 이미지 임베딩 + 판정 보류

- 상태: 채택 (2026-10-07)
- 맥락: 사용자는 업로드할 때 클럽을 입력하지 않는다(MVP 결정). 클럽군이 틀리면 엉뚱한 기준 스윙과 비교해 잘못된 지적이 나간다.
  실제로 자세 특징 모델이 앱 다운로드 드라이버 영상을 아이언으로 판별해 "스탠스가 넓어요 (공 12개)"라는 틀린 카드를 만들었다.

## 비교 (골프존 라벨 168개, 5-fold 층화 교차검증, `scripts/train_club.py`)

| 모델 | 정확도 |
|---|---|
| 자세 특징 8개 + 로지스틱 회귀 | 82.7% |
| 어드레스 공·헤드 영역 원본 픽셀 (PCA) | 80.4~82.7% |
| **MobileNetV3 임베딩(어드레스 공·헤드 영역) + 자세 특징** | **91.1%** |
| 위 + 탑(P4) 장면 임베딩 | 89.9~90.5% |

- 처음에는 잘라낸 영역이 발 주변이라 공이 빠져 있었다(정면 카메라는 위에서 비스듬히 찍어 공이 발목보다 아래). 영역을 발 아래 약 3 어깨너비로 넓혔다.
- 원본 픽셀은 매장마다 다른 조명·매트 색에 흔들린다. ImageNet 사전학습 특징(티 위의 공, 큰 둥근 헤드 vs 얇은 블레이드 같은 형태)이 매장 차이를 견딘다 → 딥러닝을 쓴 이유.
- 모델은 MediaPipe 공식 `mobilenet_v3_large` 임베더(Apache-2.0)를 그대로 쓰고 학습은 로지스틱 회귀만 한다. 데이터가 168개라 미세조정은 과적합 위험이 크다.

## 결정

- 위 조합 모델을 쓰고, **확신도 0.8 미만은 판정 보류**(카드는 자세 표시만, "클럽 판별 보류" 표시).
- 교차검증 기준: 샷 91%를 정확도 94.8%로 판별 (전부 판정하면 91.1%). 틀린 지적보다 지적 없음이 낫다.

## 한계

- 목표 95%에 근소하게 못 미친다. 다음 후보: 어드레스 여러 프레임 평균 임베딩, 업로드가 쌓이면 사용자의 "베스트로 지정" 등 암묵적 피드백으로 재학습.
- 학습 데이터가 한 사람·몇 개 매장뿐이다. 다른 체형·매장에서는 다시 검증해야 한다.
