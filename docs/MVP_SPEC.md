# 스윙 코치 피드 — MVP 명세

> 스크린골프 나스모(정면) 영상을 순서대로 업로드하면, 영상마다 "옆에서 지켜본 선생님"처럼 짧은 티칭 카드가 피드에 쌓이는 개인용 서비스.
> 작성: 2026-10-07 · 상태: **MVP 구현 완료** (아래 구현 현황)

## 구현 현황 (2026-10-11)

| 명세 항목 | 상태 | 비고 |
|---|---|---|
| 업로드(순서 유지, 이어 올리기) | ✅ | tus 방식 자체 구현(1MB 청크, 409 재동기화, 재시도). tusd 서버 대신 FastAPI 엔드포인트 |
| 처리 파이프라인 (품질·골퍼 추적·포즈·구간·지표·카드) | ✅ | 업로드→카드 약 6초 (60초 목표) |
| 구간 감지 정확도 | ✅ | 정답 30개 대비 탑 평균 오차 1.7프레임(±3 이내 93%), 임팩트 2.1, 시작 2.9. 피니시 프레임은 8.8이지만 피니시 지표는 0.3초 구간 중앙값으로 측정해 영향 0.22 SW |
| 구간 감지 실패 | ✅ | 193개 중 2개. 퍼팅·어프로치는 "풀스윙 아님" 카드 |
| 클럽 자동 판별 | ✅ | 93.5%, 확신도 0.8 이상만 판정 시 93% 샷을 95.5% — ADR 002 |
| 피드 카드 (그림 + 잘한 점·고칠 점·한마디, 기준 스윙 겹침) | ✅ | 신뢰도 낮으면 지적 생략 |
| 구질 연관 분석 | ✅ | 드라이버 슬라이스 ↔ 백스윙 골반 밀림 p=0.004 등 5개 |
| 누적 분석 화면 | ✅ | 레이크하우스 gold 마트(월별 추이·지적 빈도·라운드 요약) + 패턴 |
| 레이크하우스 (SeaweedFS·Iceberg·Lakekeeper·Trino) | ✅ | 행 해시 MERGE, 멱등, 품질 검사 23개, 업로드 후 자동 동기화 — ADR 001, 003 |
| 앱 DB Postgres | ✅ | 2026-10-11 이전, 작업 큐 `SKIP LOCKED`. SQLite는 테스트용 |
| CDC 스트림 (Debezium·Kafka) | ✅ | 앱 변경 → Iceberg 2.5~4.8초, 장애 복구 검증 — ADR 004 |
| dbt, Airflow | ✅ | gold 4개 + 테스트 19개, 야간 DAG(대조·원천 테스트·Iceberg 유지보수) |
| 카드 문장 다듬기 (로컬 LLM) | ✅ | Qwen3 8B(Ollama). 숫자·비교 기준·한국어 검사 통과 시만 교체, 채택 83% — ADR 005 |
| 내 데이터에 묻기 (text-to-SQL) | ✅ | LangGraph, 읽기 전용 SQL 검사, 실행 정확도 12/15 (3회 반복 동일) — ADR 005 |
| LLM 문장 다듬기, text-to-SQL | ⏸ | 확장 단계 |
| 테스트 | ✅ | 단위 25개(`pytest`), E2E 3개(이어 올리기, CDC, 스트림 장애 복구) |

## 1. 왜 만드는가

| 지금 | 문제 |
|---|---|
| 골프존은 샷 결과(구질·비거리)와 나스모 영상을 **따로** 보여준다 | "**왜** 훅이 났는지"를 알 수 없다 |
| 영상은 앱/웹에서 한 개씩 재생만 된다 | 내 스윙이 **좋아지고 있는지** 알 수 없다 |
| 레슨은 비싸고 매번 받을 수 없다 | 라운드 직후 짧은 피드백을 받을 곳이 없다 |

**핵심 가치**: 영상(원인)과 샷 결과(결과)를 연결해, 샷마다 *잘한 것 1개 + 고칠 것 1개 + 다음 샷 한마디*를 준다. 데이터가 쌓일수록 "내 나쁜 샷의 원인"이 선명해진다.

**하지 않는 것 (MVP 비목표)**
- 측면 영상 분석(스윙 플레인, 척추각 유지), 클럽 궤도·페이스 분석 — 정면 단일 카메라로는 측정 불가
- 실시간(샷 사이) 피드백 — 사용 시점은 **경기 종료 후**
- 다중 사용자, 레슨 프로용 기능, 결제
- 구질·클럽 수동 입력 UI, 푸시 알림 — 사용자 입력 없이 업로드만으로 동작해야 한다

## 2. 사용자 흐름

```
경기 종료 ──▶ 골프존에서 나스모 확보 ──▶ 업로드 앱에서 순서대로 업로드 (여러 개 한 번에)
                                                     │
                                                     ▼ (영상당 1분 이내 처리)
                                  피드에 영상별 티칭 카드가 순서대로 쌓임 + 그날 요약 카드
```

1. **업로드**: 앱에서 영상 여러 개를 선택 → 촬영(생성) 시각 순으로 순번이 매겨져 업로드된다. 네트워크가 끊겨도 이어 올리기.
2. **처리 중 표시**: 피드에 카드가 "분석 중"으로 먼저 나타나고 완료되면 채워진다.
3. **피드**: 최신 라운드가 위, 라운드 안에서는 샷 순번대로. 카드 = **그림 1장 + 메시지 2~3줄**. 탭하면 상세(지표·키프레임·근거).
4. **기준 스윙 지정**: 아무 카드에서 "베스트로 지정" → 이후 같은 클럽군(드라이버 / 아이언)의 비교 기준이 된다.
   - 클럽은 **영상에서 자동 판별**한다 (티 높이, 스탠스 폭, 공 위치 등). 골프존 메타가 있으면 메타가 우선.
   - 구질은 골프존 메타가 있을 때만 쓴다. 없으면 C 기준(구질 연결) 문장만 생략된다.
5. **라운드 요약 카드**: 그날 반복된 패턴 1개, 지난 라운드 대비 변화 1개.

### 피드 카드 예시

```
┌──────────────────────────────────────┐
│ 09.30 수서 골프&리조트 · 1H · 드라이버 195m · 슬라이스 │
│ ┌───────────┐ ┌───────────┐            │
│ │ P4 탑      │ │ P7 임팩트  │  내 관절선 + 기준 스윙 반투명 겹침 │
│ │  ┊➡       │ │           │  빨간 화살표 = 차이 지점          │
│ └───────────┘ └───────────┘            │
│ 👍 템포 좋아요 (3.0:1, 기준과 동일)        │
│ 👉 탑에서 머리가 기준보다 공 1개만큼 오른쪽으로 밀렸어요 │
│    다음 샷: "머리는 공 뒤, 어깨만 돌리기"      │
│ 분석 신뢰도 ●●●○ · 근거 보기 ›            │
└──────────────────────────────────────┘
```

## 4. 티칭 로직

### 4.1 판단 기준 (3단 레이어)

| 레이어 | 기준 | 시작 시점 |
|---|---|---|
| **R. 기준 스윙** | 클럽군별(드라이버 / 아이언) 사용자 지정 베스트 영상 (초기값: 스트레이트 중 캐리 상위) | MVP |
| **C. 내 좋은 샷 분포** | 같은 클럽군 스트레이트 샷들의 지표 분포 vs 휘는 샷 | MVP (드라이버 99개, 아이언 82개) |
| **A. 교습 원칙** | 템포 약 3:1 등 일반 원칙 | MVP (보조) |
| P. 프로 분포 | GolfDB 정면 프로 스윙 | 2단계 |

### 4.2 정면 시점 진단 항목

| 구간 | 지표 | 측정 (2D 관절, 어드레스 대비 상대값) |
|---|---|---|
| P1 어드레스 | 스탠스 폭, 공 위치, 상체 기울기 | 발목 간격/어깨 너비, 공(오렌지) 대 발 위치 |
| P2~P4 백스윙·탑 | **헤드 스웨이**, **골반 스웨이**, 리버스 피벗, 왼팔 굽힘 | 좌우 이동량(어깨 너비 단위), 기울기, 팔꿈치 각 |
| P5~P7 다운·임팩트 | **하체 선행**, 머리-공 위치, 핸드 퍼스트, 왼다리 지지 | 이동 시작 시점 차, 위치 비교, 무릎 각 |
| P8~P10 팔로·피니시 | 치킨윙, **체중 이동 완료**, 피니시 균형 | 팔꿈치 각, 골반 중심-왼발 위치, 정지 지속 시간 |
| 전체 | **템포**, 일관성 | 백스윙:다운스윙 시간비 (60fps, 오차 표시), 지표 편차 |

측정 불가 항목(스윙 플레인, 클럽 궤도, 척추각 유지)은 상세 화면에 "정면 영상으로는 측정 불가"로 명시한다.

### 4.3 카드 생성 규칙
1. 모든 지표를 기준(R → C → A 순 우선)과 비교해 **이탈 점수** 계산
2. **고칠 것 1개**: 이탈이 크고, 원인 순서상 앞선 것(셋업 → 백스윙 → 다운스윙) 우선
3. **잘한 것 1개**: 기준과 가장 가까운 지표, 또는 지난번보다 개선된 지표
4. **다음 샷 한마디**: 지표별 큐(cue) 사전에서 선택. 같은 지적이 3회 연속이면 표현 변경 + 드릴 제안
5. **구질 연결**: C 기준에서 해당 지표 이탈이 휘는 샷과 연관이 있으면 "이 패턴일 때 훅이 더 많았어요 (n=…)" 추가 — 연관이 확인된 경우에만
6. **신뢰도**: 관절 인식률·해상도·구간 감지 확신도로 등급. 낮으면 지적 대신 "분석 신뢰도 낮음" 표시
7. LLM은 문장 다듬기에만 사용하고, **생성 문장의 수치가 근거 수치와 다르면 폐기**

## 5. 처리 파이프라인

```
업로드(tus) ─▶ 원본 저장 ─▶ 작업 큐 ─▶ GPU 워커 ───────────────────────────▶ 피드 카드
                 │ 해시로 중복 차단      ① 품질 검사(해상도·길이) + 클럽군 자동 판별
                 │                       ② 골퍼 선택 + 비골퍼 블러
                 │                       ③ 포즈 추정 (프레임별 관절 33개)
                 │                       ④ 구간 감지 P1/P4/P7/P10
                 │                       ⑤ 지표 계산 (피처 버전 기록)
                 │                       ⑥ 기준 비교 + 카드 규칙 → 그림 렌더 + 문장
                 ▼
            레이크하우스 (pose_frame / swing / shot / feedback) ─▶ 마트 (추이·일관성·원인 분석)
```

- **멱등성**: 같은 파일(내용 해시) 재업로드 시 새 작업을 만들지 않고 기존 카드 반환
- **재시도**: 워커 실패 1회 재시도 → 실패 큐 + 알림
- **재처리**: 피처/모델 버전이 바뀌면 전체 영상 백필, 버전별 결과 비교 가능

## 6. 기술 구성 (오픈소스 전용, 데스크탑 1대)

| 영역 | MVP | 확장 (2~3단계) |
|---|---|---|
| 앱 | PWA (모바일 웹 설치형), 피드 화면만 | – |
| 업로드 | tusd (이어 올리기) | – |
| API | FastAPI | – |
| 저장 | SeaweedFS (S3 호환) | – |
| 메타·큐 | PostgreSQL (작업 큐 테이블) | Kafka (다중 사용자 시) — ADR로 전환 시점 판단 |
| 워커 | Python, MediaPipe Pose (RTX 3060) | 구간 감지 모델 직접 학습 (GolfDB) |
| 레이크하우스 | Iceberg + Lakekeeper + Trino | dbt-core 마트, Airflow 백필 |
| ML | 규칙 + 통계 비교 | LightGBM+SHAP 원인 분석, MLflow |
| LLM | Ollama (로컬, 문장 다듬기) | LangGraph text-to-SQL 에이전트 |
| 관측 | Prometheus + Grafana (처리 지연·실패율) | Marquez 리니지 |

데스크탑 제약(RAM 16GB): 프로필별로 나눠 실행, Ollama는 Windows 네이티브로 GPU 사용.

## 7. API (MVP)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/uploads` (tus) | 영상 업로드, 응답에 `video_id`·순번 |
| GET | `/videos/{id}/status` | 처리 상태 (queued / processing / done / failed) |
| GET | `/feed?cursor=` | 피드 카드 목록 (라운드·순번 정렬) |
| GET | `/cards/{id}` | 카드 상세 (지표, 근거, 키프레임 URL) |
| POST | `/reference` | 기준 스윙 지정 `{video_id, club}` |
| POST | `/import/golfzon-meta` | 메타 CSV 일괄 반영 (초기 201개 적재용) |
| POST | `/ask` | 자연어 질문 → 읽기 전용 SQL → 답변 `{answer, sql, rows}` |

## 9. 성공 기준

| 구분 | 지표 | 목표 |
|---|---|---|
| 처리 | 영상 1개 처리 시간 p95 | 60초 이내 (데스크탑) |

| 정확도 | 클럽군 자동 판별 (골프존 메타 201개를 정답으로) | 95% 이상 |
| 신뢰성 | 중복 업로드 시 중복 카드 | 0건 |
| 유용성 | 카드 "도움 됨" 비율 (본인 평가) | 70% 이상 |
| 분석 | 드라이버 스트레이트 vs 훅 간 유의한 차이 지표 | 1개 이상 발견, 효과 크기와 n 제시 |
| 품질 | 저품질 영상의 잘못된 지적 | 0건 (신뢰도 낮음으로 분기) |

## 11. ADR 후보

1. 수집 경로: 앱 다운로드(30fps HEVC) 대신 웹 원본(60fps H.264) 사용
2. 작업 큐: Kafka가 아닌 Postgres로 시작한 이유와 전환 조건
3. 광각 왜곡: 절대 각도 대신 어드레스 대비 상대 지표
4. 저해상도 영상 처리 정책 (템포 제외·신뢰도 하향)
5. 기준 스윙 방식: 프로 분포보다 개인 기준을 우선한 이유
6. LLM 사용 범위: 판단은 규칙·통계, LLM은 문장만

## 12. 정책 · 리스크

- **개인정보**: 동반자 얼굴 블러 후 저장, 공개 데모에는 본인만 노출
- **수집 스크립트**: 골프존 웹 수집 코드는 개인 용도로만 두고 **공개 레포에 포함하지 않음**. 포트폴리오에서는 "사용자 업로드" 흐름만 보여준다
- **상표**: 공개 자료에 골프존 로고·화면 캡처 사용 안 함
- **매장별 카메라 차이**: 매트·공 위치 기준 정규화, 새 매장 첫 영상은 신뢰도 하향

## 13. 결정 사항 (2026-10-07)

1. 구질·클럽 **수동 입력 없음** — 클럽군은 영상에서 자동 판별, 구질은 골프존 메타가 있을 때만 사용
2. MVP 범위는 **드라이버와 아이언 둘 다**, 기준 스윙은 클럽군별로 따로 둔다
3. **푸시 알림 없음** — 결과는 피드에서만 확인
